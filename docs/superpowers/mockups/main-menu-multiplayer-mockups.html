What each direction is arguing

01 · Nebula

The one you already have, tightened

Keeps the nebula, the twinkling stars and the cyan→magenta gradient title exactly as they ship today. The change is structural: the button column gets a real hierarchy so Multiplayer can sit beside Start Game without the row turning into a list of four equal things. Lowest risk, and nothing to relearn.

02 · Boot log

The ship is waking up, and so are you

The menu resolves out of a boot sequence — reactor, life support, comms — and the options are the last lines of the log. It makes the main menu diegetic and it makes “COMMS LINK” a natural home for multiplayer rather than a bolted-on fifth button. Costs you the big title moment.

03 · Orbit rail

Cinematic, and the calmest to read

Title and options lock to a left rail; a planet holds the right two-thirds with the camera drifting. The most conventional of the four, which is the point — it is the easiest to add items to later without redesigning, and screenshots well.

04 · Pod glass

You are already in the machine

The menu is etched on the inside of the stasis pod glass. It is the opinionated one, and it earns its place: every arrival in this game already comes out of the pod — new game, loading a save, dying, and now a second player joining. Starting the game inside the pod makes that the spine of the whole experience rather than a save-system detail.

How joining actually works now

Right now a friend has to type your IPv4 address and both machines have to be on the same network, with the right UDP port open. That is why it only ever worked on your desk. Sending the game to a friend across town cannot work that way without port forwarding, which you have already ruled out.

The fix is Unity Relay plus Unity Lobby, and it changes the shape of the problem completely. Nobody connects to anybody. Both machines make an outbound connection to a Unity-run relay server in the middle and it forwards packets between them. Outbound connections are what home routers already allow, so there is no port forwarding, no firewall prompt, and no IP address to share.

Lobby is the part that turns that into a code. When you start a session, the game creates a lobby holding your relay join code, stamps your four-digit code onto it as a searchable field, and locks it with your password. Your friend types the four digits, the game finds that lobby, the password unlocks it, and only then does it read out the relay code and connect. The relay code itself is never shown to anyone.

You have to do this bit

The project is not linked to Unity's services

Your cloudProjectId is empty and Unity Connect is switched off, so Relay and Lobby have nothing to talk to. Linking the project (Project Settings → Services) and enabling Relay + Lobby on the dashboard is a one-time job I cannot do for you. I will write you a step-by-step guide the same way the Cloudflare one works.

Solved

The password is whatever you type — or nothing

Unity's lobby field wants 8–64 characters, but the game hashes whatever you type into a fixed-length token and hands that to the service. So a 3-letter password works, and a blank one means anyone with the code can join. Both machines derive the same token from the same typed password, so Unity still checks it server-side and a wrong one never reaches netcode.

Four digits is 10,000 codes

That is plenty for you and your friends and not enough to be globally unique, so two live sessions can collide. The game handles it by rolling a new code if the one it picked is already in use — you will just see a different four digits than the one that flashed up for an instant. Worth knowing rather than being surprised by it later.

Localhost still works

The lobby screen keeps a Local toggle that bypasses Relay entirely and uses 127.0.0.1 exactly as today, so you can still run two windows side by side on your desk without touching the network, and without burning relay bandwidth while iterating.

The lever you asked for

This repo already has the right pattern for it — FeatureVault, the same const-flip that vaulted space-dust selling. Multiplayer goes behind FeatureVault.Multiplayer. Set it false and the Multiplayer button disappears from the menu, the “play together?” prompt never fires, and the game boots and plays exactly as it does today, so you can test Phase A with zero interference. Set it true and it all comes back. One line, no rebuild of anything else.

Settled, and still open

  • Settled: direction 01 as the base, with a left-aligned caret list and a rule that fills on hover.
  • Settled: Unity services get linked now, so the flow is built against Relay rather than retrofitted.
  • Open — pick a letter: which of the six option treatments above. They are all the same amount of work, so choose on feel alone.
  • Open: whether the options stay centred like today or move left with the caret. The treatments above assume left, because a caret pointing at a centred label reads oddly — but the title can stay centred above them either way.
